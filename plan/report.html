1. エグゼクティブサマリー

AIPmark5（プライバシーマーク運用支援システム）の未実装モジュール全10件について、3つのAIエージェントによる反復的な要件定義プロセスを実施しました。

  • 要件深堀エージェントが全モジュールの詳細要件を定義

2. プロジェクト概要

2.1 AIPmark5とは

プライバシーマーク（JIS Q 15001）運用を支援するNext.jsベースのWebアプリケーションです。「書類を作るシステム」ではなく、PMS運用そのものを回し、結果として申請書類・証跡・差分説明を出せるシステムという設計思想に基づいています。

2.2 技術スタック

フレームワークNext.js 15 (App Router) + React 19
言語TypeScript
DBSQLite + Prisma ORM
スタイルTailwind CSS v4（独自コンポーネント）
AIGoogle Gemini 2.0 Flash
認証NextAuth v4 (Credentials Provider)
Excel出力ExcelJS

3. 作業プロセス

3.1 エージェント構成

品質を担保するため、役割の異なる3つのAIエージェントによる反復レビュープロセスを採用しました。

エージェント役割判定権限
要件深堀エージェント 未実装機能の要件を詳細に定義。JIS Q 15001条項、ユーザーストーリー、画面設計、データモデル、API設計、AI連携、ワークフローを網羅的に記述 なし（作成者）
レビューエージェント 要件定義書を8つの観点（JIS適合性、データモデル整合性、API設計、ユーザーストーリー網羅性、AI実現可能性、既存実装との一貫性、モジュール間依存、実装可能性）で厳格レビュー 評価（A/B/C/D）+ 承認推奨/非推奨
最終承認エージェント 6つの必須基準（JIS網羅性、データモデル完全性、API一貫性、重大指摘ゼロ、実装可能性、年次運用サイクル）で合否判定 APPROVED / REJECTED

9. リスクと注意事項

9.1 実装フェーズでの注意事項

#項目内容
1Prismaマイグレーション新規テーブル約30個の一括追加。既存データへの影響を考慮し、段階的マイグレーションを推奨
2SQLiteの制約本番運用ではPostgreSQL等への移行が必要。SQLiteのJSON型サポート制約に注意
3Gemini APIコストAI連携機能が約20箇所に拡大。API利用量の監視とレート制限の実装が必要
4ファイルアップロードエビデンス・文書管理でファイル保存先の設計が必要（ローカル or クラウドストレージ）
5MVPスコープ外本人対応管理、変更管理プロセス、第三者提供管理はMVP後に対応
